Every row has a use-by date

lotel’s one promise is that telemetry forgets on schedule. This look makes that visible: retention rides along as a sticker on every screen, and the storage page draws what forgets next. Pick a look from the button at the top right; it sticks across every page in this folder.

Four colours, four jobs

Every palette assigns the same four roles. A colour never borrows another role’s job, so a reader learns the map once.

Accent: what you doThe current page, the one filled button, a picked facet value, selection. --color-accent
Second hue: what the probe measuredSeries, facet bars, latency sparks, segments on the ribbon. --color-accent-2
Red: the faultError spans, error badges, error-rate sparks, red edges. Nothing decorative is red. --color-bad
Sticker: when it forgetsTTL stickers in the top bar and on storage, the use-by line. --color-forget

Porting this into lotel

The mocks are the app’s own markup, fetched live and restyled, so almost everything is a stylesheet swap. Three markup changes are marked below.

  1. Tokens. Replace the palette blocks in skin.rs with tokens.css. It is generated by design/useby/build.py from one table, all hex (Chrome 98 has no oklch or color-mix). The token names the templates and chart JS read (--color-accent, -accent-2, -bad, -muted, -rule-2, …) are kept.
  2. Component sheet. Replace the certified sheet with useby.css. It styles every selector the current skin styles. The only :has use was dropped.
  3. Settings: port every option. The owner keeps the whole switcher until a look is picked, so ship all of it: PALETTES becomes lime, sherbet, riso, mint; FONTS becomes recursive, figtree, onest; SCHEMES is unchanged. Add STYLES (chunky, crisp) as a fourth group, a data-style attribute on <html>, and ?style= in the same cookie flow. Default: lime, day, recursive, chunky (the brief was a light look; auto stays one click away). Each option is one attribute selector in tokens.css, so trimming later is deleting rows from the consts and blocks from the sheet.
  4. Rename before release. The shipped palettes are named honeycomb and motherduck, and the popover’s deep-link example mentions one. Both are other companies’ marks; the new names avoid them.
  5. Fonts. lotel is local-first, so embed the woff2 files with include_bytes! and serve them from /assets/fonts/ instead of Google Fonts. Embed all of them (Recursive, Figtree, Spline Sans Mono, Onest, DM Mono, latin subset, roughly 0.5 to 1 MB of binary); browsers only download a face a page actually uses, so the unused pairings cost binary size, not page weight. Recursive needs one file for every role.

Markup deltas

1. Retention stickers in the top bar. In ui.rs, render <div class="useby-strip"> before the settings popover inside header.top, one .useby per signal from Config.ttl_logs / ttl_traces / ttl_metrics.

2. Thousands separators on stat tiles (.card.stat .n) and facet counts. Format in Rust, not CSS.

3. The use-by ribbon on /storage, above the tables: one .ribbon-row per table from capped_status. Each segment is a .seg (.seg-open when unsealed) with left = (min_ts − (now − ttl)) / ttl and width = (max_ts − min_ts) / ttl. The right column names the oldest sealed segment and its countdown max_ts + ttl − now. Use the server clock for now; the mock uses the newest row because its data is old. Reference implementation: storage_ribbon() in build.py.
